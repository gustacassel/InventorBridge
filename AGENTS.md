# Working on InventorBridge

Instructions for AI agents (and people) changing this repository. To *use* InventorBridge with Inventor, see the README and `skills/inventor-api/SKILL.md`.

## Build and test

- Build the server: `dotnet build src/InventorBridge.Mcp -c Release`. It needs `Autodesk.Inventor.Interop.dll` from an Inventor 2024 installation or `lib/inventor/2024/` (see `InventorInterop.props`).
- Tests: `dotnet test`. They run without Inventor: API lookup, guides (every C# block in `docs/guides` must compile as a `run_csharp` script), script compilation, the change list, and the server over stdio (tool list and the four MCP hints on every tool).
- When you add a tool, add it to `ExpectedTools` in `tests/InventorBridge.Mcp.Tests/ServerTests.cs` and give it all four hints (`ReadOnly`, `Destructive`, `Idempotent`, `OpenWorld`).

## Testing against a real Inventor

Most behavior only shows on a running Inventor: dialogs, transactions, localized names, large assemblies. When one is available:

- Drive the built server over stdio with a small MCP client (initialize, then `tools/call`), and test each change on real documents.
- Save test files outside the user's project workspace, and never save over the user's files: open them, read them, close them with `Close(true)`.
- Add-ins can open dialogs that hold a call (Vault Data Standard on every save of a new file). Check for Inventor's windows when a call hangs, and say what you closed.
- Record what you verified, and what you could not, in `ARCHITECTURE.md` under the phase it belongs to.

## Conventions

- `docs/reference` is generated by `src/InventorBridge.ReferenceGenerator` from the interops of every supported version: do not edit it by hand, and do not regenerate it with only some versions present, or the others' members disappear.
- The Autodesk DLLs and Autodesk's documentation text never go into the repository.
- The repository is public and company-neutral. A company's standards (numbering, ERP codes, templates, vault rules) belong in that company's own repository, as guides the server loads from `INVENTORBRIDGE_GUIDES`.
- Guides in `docs/guides` are short, in plain English, and only claim what was run on Inventor or compiled by the tests. Each guide's C# blocks are scripts the guide tests compile.
- Tool results are written for an agent: say what happened, what was not done, and what to do next.
